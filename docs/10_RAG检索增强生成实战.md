# 10 RAG 检索增强生成实战

## 1. RAG 是什么

RAG（Retrieval-Augmented Generation，检索增强生成）在生成回答前，先从知识库检索相关片段，
再把片段作为上下文交给大模型。它解决两个问题：

- **知识过时/私有**：模型训练语料里没有的内容，可以从知识库补充；
- **幻觉**：要求模型“只根据资料回答”，并给出引用。

典型流程：

```text
文档 -> 切块 -> embedding -> 写入 Milvus
                                 │
用户问题 -> embedding -> 向量检索 -> Top-K 片段
                                 │
                        拼装 Prompt -> LLM -> 带引用的回答
```

Milvus 负责中间的“存储 + 语义检索”。

## 2. 切块（Chunking）

切块质量直接决定检索质量。常见策略：

| 策略 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| 固定长度 | 每 N 字符切一刀 | 简单 | 可能切断句子/语义 |
| 按句子/段落 | 按标点、换行聚合 | 语义完整 | 长度不均 |
| 递归切分 | 段落 → 句子 → 字符 | 平衡 | 实现稍复杂 |
| 语义切分 | 用模型判断边界 | 质量高 | 成本高 |

本项目的做法（`mlcore/rag.py`）：

- 先按中文句末标点（。！？；）和换行切句；
- 在 `max_chars=180` 左右聚合，尽量在句子边界断开；
- 相邻块保留 `overlap=30` 个字符，减少边界信息丢失；
- 向量化文本是 `标题 + 片段`，存储文本仍是片段原文。

参数经验：

- 片段太短：语义不完整，召回噪声大；
- 片段太长：一个向量混入多个主题，相似度被稀释；
- 中文技术文档 150–400 字通常是不错的起点。

## 3. 检索

```python
hits = mlcore.rag.retrieve(
    client,
    collection,
    question,
    embedder,
    top_k=4,
    category=None,
    max_per_doc=2,
)
```

要点：

- 先多取候选（`top_k × 3`），再按文档去重；
- 同一文档最多保留 2 个 chunk，避免上下文被单一文档占满；
- 可以加分类/时间过滤，缩小检索范围；
- 生产环境通常还会加混合检索（dense + BM25）和重排。

## 4. Prompt 设计

本项目使用的系统提示：

```text
你是一个严谨的中文学习助手。请只根据用户提供的编号资料回答问题。
如果资料不足以回答，请明确说“资料中没有足够信息”，不要编造。
回答时用 [1]、[2] 标注引用来源。
```

用户提示：

```text
资料：
[1] 《标题》 分类：...
内容：...
[2] ...

问题：...
```

设计原则：

1. **编号资料**：方便模型引用，也方便你核对；
2. **拒答指令**：明确“资料不足就说不足”，降低幻觉；
3. **限制来源**：只允许使用给定资料，不引入外部知识；
4. **控制长度**：Top-K 不宜过大，否则超出上下文或稀释重点。

## 5. 离线回答与在线生成

本项目默认 `RAG_LLM=offline`：

- 从每个命中片段抽取第一句，按相关度顺序拼接；
- 明确标注“离线抽取式回答，未调用大模型”；
- 末尾给出引用编号。

配置 `RAG_LLM=openai` 且提供 `OPENAI_API_KEY` 后：

- 调用 OpenAI 兼容的 `/chat/completions`；
- `temperature=0.2`，减少发散；
- 网络失败自动回退离线回答，不中断 demo。

> 隐私：开启在线生成后，问题与检索片段会发送到你配置的外部服务。
> 默认离线模式不会发出任何网络请求。

## 6. 评估 RAG

可以从四个维度观察：

| 维度 | 指标 | 怎么测 |
|---|---|---|
| 检索 | Recall@K、MRR | 准备问答对，看正确片段是否在 Top-K |
| 忠实度 | 回答是否只依据资料 | 人工抽查 + 引用核对 |
| 完整性 | 是否覆盖问题要点 | 人工评分 |
| 性能 | 检索延迟、生成延迟、总耗时 | 计时日志 |

小项目不必一上来就搭评估平台，先准备 20–50 个真实问题，人工看 Top-K 是否合理。

## 8. 常见问题

**回答为空或答非所问**

- 检查检索 Top-K 是否包含正确片段；
- 伪向量语义能力有限，换真实 embedding 往往立竿见影；
- 调整切块大小/重叠；
- 加分类过滤，减少噪声。

**回答编造**

- 强化系统提示中的拒答要求；
- 降低 `temperature`；
- 只给编号资料，不额外提供“常识”；
- 人工核对引用编号。

**上下文太长**

- 减少 Top-K；
- 限制每个文档的 chunk 数；
- 压缩片段或先做摘要。
