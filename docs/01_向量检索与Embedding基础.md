# 01 向量检索与 Embedding 基础

## 1. 从关键词检索到语义检索

传统关键词检索按字面匹配：

- 搜“向量数据库”能找到包含这五个字的文档；
- 搜“相似度搜索工具”却可能找不到写着“向量检索系统”的文档。

语义检索先把文本映射成**向量**（一串浮点数），再比较向量之间的距离。
意思相近的文本，即使没有共同字词，向量也应当接近。

```text
"如何选择向量数据库"  -> [0.12, -0.03, 0.88, ...]
"Milvus 选型建议"     -> [0.10, -0.01, 0.85, ...]   # 方向接近
"红烧肉的做法"        -> [-0.77, 0.42, 0.05, ...]  # 方向很远
```

把文本变成向量的过程叫 **Embedding（嵌入）**。模型决定了向量的“语义质量”，
而数据库负责在海量向量中快速找到最接近的那些。

## 2. 向量、维度与归一化

- **维度**：向量的分量个数。常见文本 embedding 为 384、768、1024、1536、3072 维。
- **稠密向量**：每个维度都有值，适合表达整体语义。
- **稀疏向量**：绝大多数维度为 0，只有出现过的词对应非零值，适合关键词/全文检索。
- **归一化**：把向量缩放成长度为 1。归一化后，余弦相似度与内积相等：

```text
cos(a, b) = (a · b) / (|a| × |b|)
若 |a| = |b| = 1，则 cos(a, b) = a · b
```

## 3. 三种常用度量

| 度量 | 公式 | 关注点 | 典型场景 |
|---|---|---|---|
| 余弦 COSINE | `a·b / (|a||b|)` | 方向是否一致 | 文本 embedding |
| 内积 IP | `a·b` | 方向 + 模长 | 已归一化向量、推荐 |
| 欧氏距离 L2 | `sqrt(Σ(aᵢ-bᵢ)²)` | 绝对距离 | 图像/音频特征 |

Milvus 中的分数方向不同：

- **COSINE / IP**：分数越大越相似，通常范围约 `[-1, 1]`（IP 可超出）。
- **L2**：距离越小越相似，0 表示完全相同。

> 索引创建时声明的 `metric_type` 必须与搜索时一致。混用 COSINE 和 L2 不会“自动换算”，
> 结果没有可比性，部分版本还会直接报错。

## 4. 精确检索与 ANN

给定查询向量，最直接的做法是计算它与所有向量的距离，取前 K 个，这叫 **KNN（精确最近邻）**。
数据量大时（百万、十亿级），逐个计算不可接受。

**ANN（近似最近邻）** 用索引结构牺牲少量召回率，换取数量级的速度提升。
核心权衡：

```text
召回率  ↑  ←→  查询延迟 ↓
内存    ↑  ←→  建索引时间 ↓
```

常见索引：

- **FLAT / BRUTE_FORCE**：暴力精确检索，作为效果基线。
- **IVF 系列**：先用聚类把向量分桶，查询时只搜少数桶（`nprobe` 控制搜几个桶）。
- **HNSW**：多层图结构，从稀疏高层逐层下降到稠密底层，低延迟、高召回，内存占用较高。

## 5. HNSW 直觉

把向量想象成地图上的点：

- 最上层点很少，边很长，用于快速接近目标区域；
- 越往下点越密，边越短，用于精细定位；
- 查询从最上层入口开始，每层贪心地走向离查询更近的邻居，然后进入下一层。

三个关键参数：

| 参数 | 作用 | 增大后的影响 |
|---|---|---|
| `M` | 每个节点的邻居数 | 召回↑、内存↑、建索引慢 |
| `efConstruction` | 建图时每层候选队列大小 | 图质量↑、建索引慢 |
| `ef`（查询时） | 查询候选队列大小 | 召回↑、延迟↑ |

经验起点：`M=16`、`efConstruction=200`、查询 `ef=64~128`，再根据数据量和召回要求调整。

## 6. 本项目的伪向量

`mlcore/embedding.py` 中的 `PseudoEmbedder` 不是神经网络，而是一个确定性特征哈希：

1. **分词**：中文按单字 + 相邻二元组，英文/数字按词切分；
2. **哈希**：用 SHA-256 把每个 token 映射到固定维度的某个位置，并用摘要位决定正负；
3. **加权**：二元组、英文词权重更高，单字权重较低；
4. **概念注入**：文本包含“检索/搜索”“部署/集群”“美食/面条”等关键词时，
   额外注入一个高权重概念特征，让同义表达产生一定重叠；
5. **归一化**：最终向量长度为 1。

优点：完全离线、结果可复现、能直观演示“共享词越多越相似”。
局限：没有学习到的语义，不做 IDF，真正的同义改写只能靠少量概念词表。
所以 demo 中“向量数据库怎么选型”能召回 Milvus 文档，但不要期待它理解复杂隐喻。

## 7. 对应 Demo：`02_embeddings_and_similarity.py`

脚本会：

1. 打印几条文本的向量维度、范数和前几个分量；
2. 计算同主题/跨主题句子的余弦相似度，观察差值；
3. 用 25 条语料计算查询的暴力 Top-K，与后面 Milvus 的 ANN 结果对照；
4. 比较 64 / 128 / 256 维下 Top-1 是否稳定。

运行：

```bash
venv\Scripts\python.exe demos\02_embeddings_and_similarity.py
```

观察点：

- 相同文本两次 embedding 是否完全一致（确定性）；
- 同主题相似度是否明显高于无关主题；
- 维度降低后，排名是否开始抖动。
