# 04 索引类型与参数调优

## 1. 索引解决什么问题

没有向量索引时，查询要扫描全部向量（FLAT），复杂度 O(N)。
索引用额外的内存和构建时间，把查询复杂度降到接近 O(log N) 或 O(候选集大小)。

三个成本维度：

```text
查询延迟  ←→  召回率
内存占用  ←→  索引构建时间
```

没有“最好”的索引，只有适合当前数据量、召回要求和硬件预算的索引。

## 2. 常见索引类型

| 索引 | 原理 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| `FLAT` / `BRUTE_FORCE` | 暴力扫描 | 100% 召回、零构建 | 慢 | 小数据、效果基线 |
| `IVF_FLAT` | 聚类分桶，查询搜 `nprobe` 个桶 | 内存可控、构建快 | 需要训练、边界召回损失 | 中等规模 |
| `IVF_SQ8` | IVF + 标量量化到 8 bit | 内存约为 1/4 | 有量化误差 | 内存敏感 |
| `HNSW` | 多层近邻图 | 低延迟、高召回 | 内存高、构建慢 | 在线低延迟 |
| `HNSW_SQ` | HNSW + 量化 | 内存降低 | 召回略降 | 内存受限的在线场景 |
| `AUTOINDEX` | 由服务端选择 | 省心 | 参数不可控 | 快速原型/托管服务 |
| `SPARSE_INVERTED_INDEX` | 稀疏倒排 | 关键词/BM25 | 只适合稀疏向量 | 全文检索 |
| `INVERTED` | 标量倒排 | 加速过滤 | 高基数字段收益低 | 分类、标签、布尔 |

> Milvus Lite 3.2 支持 HNSW、HNSW_SQ、IVF_FLAT、IVF_SQ8、FLAT、BRUTE_FORCE、AUTOINDEX、
> SPARSE_INVERTED_INDEX 和标量 INVERTED；不支持 PQ、BINARY、FLOAT16/BF16、INT8 向量。

## 3. HNSW 参数

```python
index_params.add_index(
    field_name="embedding",
    index_type="HNSW",
    metric_type="COSINE",
    params={"M": 16, "efConstruction": 200},
)
```

搜索时：

```python
search_params = {"metric_type": "COSINE", "params": {"ef": 64}}
```

| 参数 | 阶段 | 作用 | 调大 |
|---|---|---|---|
| `M` | 建索引 | 每个节点的邻居数 | 召回↑、内存↑、构建慢 |
| `efConstruction` | 建索引 | 建图候选队列 | 图质量↑、构建慢 |
| `ef` | 查询 | 查询候选队列 | 召回↑、延迟↑ |

经验：

- `M` 常用 8–64，文本场景 16 起步；
- `efConstruction` 常用 100–400；
- 查询 `ef` 必须 ≥ `limit`，通常取 `limit` 的 2–10 倍；
- 先用 FLAT 得到“标准答案”，再调 HNSW，观察召回损失。

## 4. IVF 参数

```python
index_params.add_index(
    field_name="embedding",
    index_type="IVF_FLAT",
    metric_type="L2",
    params={"nlist": 128},
)
search_params = {"metric_type": "L2", "params": {"nprobe": 16}}
```

- `nlist`：聚类桶数。数据越多，`nlist` 越大；经验值 `sqrt(N)` 到 `4*sqrt(N)`。
- `nprobe`：查询时搜索的桶数。越大越接近精确检索，延迟越高。
- IVF 需要训练数据；数据量太小时，聚类没有意义，反而可能不如 FLAT。

## 5. 标量索引与稀疏索引

- 标量字段（分类、标签、年份、布尔）建 `INVERTED` 索引，可以加速 `==`、`in`、范围过滤。
- 稀疏向量建 `SPARSE_INVERTED_INDEX`：
  - 手动稀疏向量用 `metric_type="IP"`；
  - BM25 Function 生成的稀疏字段用 `metric_type="BM25"`。

不要把 BM25 字段和普通稀疏字段的 metric 混用：Milvus 3.2 会明确报错，而不是静默改写。

## 6. 索引什么时候需要重建

- 向量维度或 embedding 模型改变：必须重建 collection；
- 数据分布发生大幅变化：考虑重建 IVF（聚类中心失效）；
- 大量删除/更新后：等待 compaction，必要时重建以回收空间；
- 索引参数不合适：先在小规模副本上对比，再滚动重建。

## 7. 选择决策表

| 数据规模 | 延迟要求 | 推荐 |
|---|---|---|
| < 10 万 | 任意 | FLAT（简单、精确） |
| 10 万–1000 万 | 低延迟 | HNSW |
| 10 万–1000 万 | 内存敏感 | IVF_SQ8 / HNSW_SQ |
| > 1000 万 | 低延迟 | HNSW（分片/多副本）或托管 AUTOINDEX |
| 关键词/全文 | — | BM25 + SPARSE_INVERTED_INDEX |
| 元数据过滤 | — | 标量 INVERTED |

## 8. 对应 Demo：`04_schema_and_index.py`

脚本会创建三个 collection：

- `docs_flat`：FLAT + COSINE，作为精确基线；
- `docs_hnsw`：HNSW + COSINE；
- `docs_ivf`：IVF_FLAT + L2（注意度量不同，分数不可直接比较）。

然后：

1. 打印 `describe_index` 的结果；
2. 对同一查询分别取 Top-5；
3. 计算 FLAT 与 HNSW 的排名重合度；
4. 说明小数据下 IVF 的 `nprobe` 调参意义有限。

运行：

```bash
venv\Scripts\python.exe demos\04_schema_and_index.py
```
