# 08 稀疏向量与 BM25 全文检索

## 1. 稠密与稀疏

| | 稠密向量 | 稀疏向量 |
|---|---|---|
| 形式 | 每个维度都有值 | 绝大多数维度为 0 |
| 维度 | 384/768/1536… | 通常等于词表大小（很大） |
| 存储 | 定长数组 | `{index: weight}` |
| 擅长 | 语义相似 | 关键词精确匹配 |
| 典型来源 | 神经网络 embedding | BM25、TF-IDF、SPLADE |

稀疏向量的一个例子：

```python
{1024: 1.8, 88: 0.9, 65530: 2.1}
```

只存非零项，所以“高维稀疏”并不等于“存储爆炸”。

## 2. 倒排索引

稀疏向量天然适合倒排：

```text
词项 1024 -> [doc1: 1.8, doc7: 0.4]
词项 88   -> [doc1: 0.9, doc3: 1.2]
```

查询时只访问包含查询词项的文档，避免扫描全库。
Milvus 中对应 `SPARSE_INVERTED_INDEX`。

## 3. BM25 公式直觉

BM25 综合三件事给文档打分：

1. **词频 TF**：词出现越多越相关，但有饱和（不会无限加分）；
2. **逆文档频率 IDF**：越少见的词越有区分度；
3. **文档长度归一化**：长文档天然包含更多词，需要惩罚。

简化形式：

```text
score(D, Q) = Σ IDF(qᵢ) × [ tf × (k1 + 1) ] / [ tf + k1 × (1 - b + b × |D| / avgdl) ]
```

- `k1` 控制词频饱和速度，常用 1.2；
- `b` 控制长度归一化强度，常用 0.75；
- IDF 常用 `ln(1 + (N - n + 0.5) / (n + 0.5))`。

BM25 的分数和余弦分数**没有可比性**：一个是词项加权，一个是向量方向。
另外，Milvus 为了统一“距离越小越好”的接口，BM25 结果通常以**负分**返回，
因此分数越小（越负）越相关；这与 COSINE 的“越大越好”相反。

## 4. Milvus 中的 BM25

推荐用 Schema Function 让 Milvus 自动完成“分词 → 生成稀疏向量”：

```python
schema.add_field(
    "text", DataType.VARCHAR, max_length=65535, enable_analyzer=True, enable_match=True
)
schema.add_field("sparse", DataType.SPARSE_FLOAT_VECTOR)
schema.add_function(
    Function(
        name="bm25",
        function_type=FunctionType.BM25,
        input_field_names=["text"],
        output_field_names=["sparse"],
    )
)
```

建索引：

```python
index_params.add_index(
    field_name="sparse",
    index_type="SPARSE_INVERTED_INDEX",
    metric_type="BM25",
    params={},
)
```

搜索时直接传原始文本：

```python
client.search(
    collection_name="articles",
    data=["向量检索怎么选型"],
    anns_field="sparse",
    limit=5,
    output_fields=["text"],
)
```

要点：

- 不要手动写 `sparse` 字段；它由 Function 生成；
- 不要给 BM25 字段传预计算向量；
- analyzer 决定分词质量，中文需要确认是否启用 Jieba/中文分析器。

## 5. Analyzer 与中文分词

- `standard`：按空白/标点切分，适合英文；
- 中文分析器（如 Jieba）：把“向量数据库”切成“向量/数据库”等词；
- 如果不用中文分析器，中文长句可能被当成一个 token，BM25 效果会很差。

本项目在 `BM25_MODE=auto` 下会依次尝试中文分析器配置，失败则回退：

- `native`：使用 Milvus 原生 BM25；
- `manual`：用 `mlcore/sparse.py` 生成 TF 稀疏向量 + `metric_type="IP"`。

回退方案能在任何环境跑通，但它**不是 BM25**，只是教学替身。

## 6. 手动稀疏向量

当原生 BM25 不可用时：

```python
vector = manual_sparse("Milvus 支持稀疏向量")   # {index: weight}
rows = [{"id": 1, "sparse": vector, ...}]
```

搜索时查询向量也要用同样的函数生成，索引使用 `SPARSE_INVERTED_INDEX + IP`。
由于哈希后的索引空间很大，冲突概率低，但语义仍是词项匹配而非 BM25 统计。

## 7. 对应 Demo：`07_sparse_bm25.py`

脚本会：

1. 尝试创建 BM25 Function 的 collection；
2. 插入 25 条语料；
3. 用关键词查询（如“向量 检索”“火锅”）做 BM25 搜索；
4. 与稠密向量搜索结果对比；
5. 原生 BM25 失败时自动切手动稀疏，并打印“手动稀疏回退”标识。

运行：

```bash
venv\Scripts\python.exe demos\07_sparse_bm25.py
```

观察点：

- BM25 对精确关键词很敏感；
- 稠密检索对同义表达更宽容；
- 两种分数不能直接比较大小。
