# 07 分区、分区键与别名

## 1. Partition 是什么

Partition 是 collection 内的逻辑划分。每个实体最终属于一个 partition，
查询时可以只搜索指定 partition，从而减少扫描范围。

```python
client.create_partition(collection_name="docs", partition_name="cat_food")
client.insert(collection_name="docs", data=rows, partition_name="cat_food")
client.search(..., partition_names=["cat_food"])
```

适用场景：

- 按时间分区：按月/按天，过期数据直接 drop partition；
- 按业务线/租户隔离：不同租户的数据物理分开；
- 冷热分离：热数据单独加载。

注意：

- 分区名必须是合法标识符，建议用 ASCII（中文分类名请映射成 `cat_food` 等）；
- 分区过多会增加元数据与调度开销；
- Milvus Lite 的 gRPC 适配器**不支持分区级 load/release**，只能整 collection load；
  `partition_names` 搜索仍可用。

## 2. Partition Key（分区键）

不想手动管理分区时，可以把某个标量字段声明为分区键：

```python
schema.add_field("tenant_id", DataType.VARCHAR, max_length=64, is_partition_key=True)
```

Milvus 会按 `tenant_id` 的哈希自动把数据路由到内部分区（默认分区数由 `num_partitions` 控制，
常见默认值为 16）。查询时：

- 不需要指定 `partition_names`；
- 在过滤条件中带上 `tenant_id`，系统可以自动裁剪到对应分区。

适合：

- 多租户 SaaS；
- 高基数但查询总带同一维度条件；
- 不想手工维护分区列表。

不适合：

- 基数极低（只有两三个值）——普通过滤就够；
- 查询不带分区键条件——会退化为扫描所有分区。

## 3. 三种隔离手段怎么选

| 手段 | 隔离粒度 | 管理成本 | 适用 |
|---|---|---|---|
| 普通标量过滤 | 逻辑 | 最低 | 低基数、查询灵活 |
| Partition | 物理（手动） | 中 | 时间分区、批量删除、冷热分离 |
| Partition Key | 物理（自动） | 低 | 多租户、高基数、查询总带该字段 |

## 4. Alias（别名）

别名是指向 collection 的间接引用：

```python
client.create_alias(collection_name="docs_v1", alias="docs_current")
client.alter_alias(collection_name="docs_v2", alias="docs_current")
client.drop_alias(alias="docs_current")
```

用途：

- **蓝绿切换**：先建好 `docs_v2` 并灌数据、建索引，再把别名切过去，应用无需改代码；
- **版本管理**：应用只认别名，底层 collection 可以滚动重建；
- **回滚**：切回旧 collection 即可。

注意事项：

- 别名在同一 database 内唯一；
- 写入路径如果也用别名，切换后新数据会写入新 collection；
- 删除被别名引用的 collection 前，先处理别名。

## 5. load / release

查询前需要 `load_collection`，把数据和索引加载到 Query Node 内存：

```python
client.load_collection(collection_name="docs")
client.release_collection(collection_name="docs")
```

- 远程 Milvus 支持按 partition load/release；
- Milvus Lite 只支持整 collection 级别的加载；
- demo 中的 `ensure_loaded` 会忽略“已加载”的重复调用。

## 8. 常见坑

- 分区名包含中文或特殊字符，创建失败；
- 插入时 `partition_name` 拼错，数据进了默认分区；
- 查询只传 `partition_names` 但没 load 对应分区（远程）；
- 删除 collection 前忘记先删除别名；
- Milvus Lite 3.2 的 `count(*)` 会忽略 `partition_names`，按分区计数时需要取回 `id` 再计数。
