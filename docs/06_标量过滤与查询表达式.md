# 06 标量过滤与查询表达式

## 1. 过滤表达式是什么

Milvus 的过滤表达式是一种**受控的布尔表达式**，不是 SQL，也不是任意代码。
它支持比较、逻辑组合、集合判断、字符串前缀、JSON 路径和数组函数。

过滤可以用于：

- `query(filter=...)`：只按标量条件取数据；
- `search(filter=...)`：向量检索 + 标量过滤；
- `delete(filter=...)`：按条件删除。

## 2. 基础语法

```python
# 比较
"year >= 2020"

"rating > 4.5"
"is_free == true"

# 逻辑组合
'category == "美食" and year >= 2022'
'(category == "旅行" or category == "电影") and rating >= 4.5'

# 集合
'category in ["美食", "旅行"]'
"id not in [1, 2, 3]"

# 字符串前缀（like 只支持前缀匹配）
'author like "美食%"'
```

规则：

- 字符串用**双引号**；中文值可以直接写在表达式中；
- 布尔值写 `true` / `false`；
- 字段名区分大小写；
- 不要拼接未校验的用户输入，避免表达式注入。

## 3. JSON 与数组

语料中的 `meta` 是 JSON，`tags` 是 ARRAY：

```python
# JSON 路径
'meta["level"] == "进阶"'

'meta["source"] == "官方文档"'

# 数组包含
'ARRAY_CONTAINS(tags, "Milvus")'
"ARRAY_LENGTH(tags) >= 3"

# JSON 包含（对象/数组）
'json_contains(meta, "入门")'
```

注意事项：

- JSON 深层路径的过滤成本高于普通标量字段；
- 频繁过滤的 JSON 键，考虑提升为独立字段；
- 不同 Milvus 版本对 JSON 函数的支持略有差异，以 `00_environment_check.py --deep` 的输出为准。

## 4. 空值与存在性

```python
'meta["level"] is null'

'meta["level"] is not null'
'exists meta["source"]'
```

对于动态字段（未在 Schema 声明），可以用 `$meta` 访问：

```python
'$meta["color"] == "red"'
```

## 5. 全文匹配

如果字段开启了 `enable_analyzer=True` 和 `enable_match=True`，可以使用：

```python
'text_match(text, "向量 检索")'
```

这属于全文/BM25 能力的入口之一，和向量相似度是两条不同的召回路径。

## 6. query 与 search 的组合

```python
# 只取标量数据
rows = client.query(
    collection_name="docs",
    filter='category == "美食" and year >= 2022',
    output_fields=["title", "year", "rating"],
)

# 向量检索 + 过滤
hits = client.search(
    collection_name="docs",
    data=[query_vector],
    filter='category == "美食"',
    limit=5,
    output_fields=["title", "category"],
)
```

`query` 不计算向量相似度；它适合做统计、校验、导出。
`search` 返回的条数可能少于 `limit`，因为过滤后候选不足。

## 7. 性能建议

1. **给过滤字段建标量索引**：`index_type="INVERTED"`；
2. **高选择性条件优先**：先缩小候选集；
3. **少用复杂 JSON 路径**；
4. **结合分区裁剪**：租户/时间分区比表达式过滤更高效；
5. **避免前导通配符**：`like "%foo"` 不受支持或无法利用索引。
